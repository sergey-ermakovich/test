# Zeekr Журнал

Бортжурнал для головного устройства Zeekr 7X (Android 12, Qualcomm SA8295):
учёт зарядок и расхода электричества с живыми данными машины.

Пакет тот же (`com.zeekrprobe`), что и у прежнего диагностического «Probe», —
обновление ставится поверх. Диагностический экран никуда не делся, он теперь
за кнопкой «Диагностика машины» на главном экране.

## Что умеет

* **Главная** — крупный индикатор заряда (SoC), запас хода и одометр живьём из
  ECARX; плитки со средним расходом (кВт·ч/100 км), стоимостью (руб/км),
  тратами за месяц и всего.
* **Зарядки** — список сессий. Кнопка «+» добавляет зарядку: выбираешь сеть из
  списка (Маланка, BatteryFly, Evika, Zaradka, Дом, Другое) — цена
  подставляется сама (последняя по этой сети, иначе тариф из справочника, у
  Zaradka ночной 0,48 с 21:00 до 08:00 учитывается по времени). Достаточно
  ввести что-то одно — кВт·ч **или** сумму, остальное посчитается по цене.
* **История** — отрезки между соседними зарядками: сколько км проехал, сколько
  залил, расход и стоимость именно на этом участке (одометр → одометр).
* **Автоопределение зарядки** — фоновый сервис следит за мощностью зарядки и
  приростом заряда; если зарядку забыл записать, он создаёт черновик сессии,
  который остаётся подтвердить и вписать цену. Работает, когда приложение
  свёрнуто.

Расход и руб/км считаются «от розетки»: энергия, залитая на очередной зарядке,
относится к пробегу с прошлой зарядки. Это самый честный платёжный расход и он
не ломается, если одну зарядку пропустить (поможет автоопределение).

Ничего не меняет в машине: только читает и показывает.

## Диагностика (прежний Probe)

Кнопка «Диагностика машины (ECARX)» на главном открывает прежний экран:
проверка установки стороннего APK, состояние ADB, выданные разрешения и полный
дамп доступных сигналов ECARX AdaptAPI и car-service.

## Где взять APK и как поставить

Каждый push собирает APK в GitHub Actions и публикует в **Releases**:

* `ZeekrProbe-N.apk` — основной APK для машины, пакет `com.zeekrprobe`.

Был ещё вариант с подписью платформенным ключом AOSP (`com.zeekrprobe.sys`) —
проверяли, не на тестовых ли ключах прошивка. Ключ у Zeekr свой, прав это не
добавляло, поэтому вариант убран.

Установка из браузера ГУ: открыть страницу релиза, скачать `.apk`, открыть из
«Файлов». Штатный файловый менеджер может отказать («нужно разрешение на
установку», а настройки не открываются) — тогда помогает установка через
APKPure или через ADB.

### NetInfo — помощник для телефона

`NetInfo-N.apk` (из того же релиза) ставится **на телефон**. Показывает IP
телефона, шлюз и список соседних устройств, а по кнопке «Сканировать :5555»
помечает, у кого открыт ADB-порт — то есть сразу видно адрес машины и готовую
строку `adb connect <ip>:5555`. Удобно, когда телефон и машина раздают друг
другу интернет и непонятно, какой у кого адрес.

### ADB без кабеля и без ноутбука

На ГУ открыт ADB по сети (`service.adb.tcp.port=5555`, `adbd` запущен).
Телефон в одну Wi‑Fi сеть с машиной (точка доступа машины или общий роутер),
приложение **Bugjaeger Mobile ADB** → connect `<IP машины>:5555` → Install APK.
С компьютера: `adb connect <IP>:5555`, дальше `adb install -r ZeekrProbe-N.apk`.
IP машины печатается в секции `ADB` отчёта.

## Самообновление

Кнопка **Обновить APK** качает последний релиз с GitHub и открывает системный
установщик (или APKPure) на скачанном файле. ADB не используется: на этой
прошивке adbd слушает только USB, подключение к `127.0.0.1:5555` отваливается
по таймауту.

* **Обновить APK** — ставит, только если в релизе есть версия новее.
* **Переустановить** — ставит последнюю принудительно.
* Долгое нажатие на «Обновить APK» — ввод токена GitHub.
* Первый раз на экране ГУ может появиться запрос на подтверждение ADB-ключа —
  подтвердить один раз, ключ сохраняется в приложении.

**Приватный репозиторий:** GitHub API не отдаёт релизы приватной репы без
авторизации. Либо сделать репозиторий публичным (тогда обновление работает
само), либо создать fine-grained token с доступом **Contents: Read** к этой
репе и вставить его долгим нажатием на «Обновить APK».

## Выгрузка отчёта на свой хостинг

Файловый менеджер ГУ не даёт сохранять и копировать файлы, поэтому кнопка
**Выгрузить** шлёт отчёт POST-запросом на `server/upload.php`.

1. Положить `server/upload.php` на любой PHP-хостинг, рядом создать папку
   `reports/` с правом записи, в скрипте поменять `TOKEN`.
2. В приложении удерживать кнопку «Выгрузить», ввести адрес скрипта и токен —
   они хранятся в настройках приложения, в APK ничего не зашито.
3. Список отчётов: `upload.php?token=T&list=1`, сам отчёт:
   `upload.php?token=T&file=<имя>`.

## Что уже известно по отчётам с машины

* Стандартный `android.car` подключён к заглушке (`INFO_MAKE = "Toy Vehicle"`),
  реальных данных там нет.
* Данные машины у Zeekr идут через ECARX AdaptAPI
  (`com.ecarx.xui.adaptapi.car.Car`, сервис `adapt_service`); так работают
  открытые проекты [zeekr-shortcut-car](https://github.com/dts88/zeekr-shortcut-car)
  и [zee-power-toys](https://github.com/maxim-saplin/zee-power-toys).
  На китайской прошивке 7X сигнатура `Car.create` отличается от зарубежной —
  пробник подбирает её.
